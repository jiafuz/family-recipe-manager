## 1. 文档用途

本文用于持续记录“家宴”微信小程序的：

- 已完成产品与工程能力。
- 当前已知问题和功能缺口。
- 内测、公开测试和正式上线前的任务。
- 推荐开发顺序与发布门槛。

任务状态约定：

- `[x]`：已经完成并进入当前代码基线。
- `[ ]`：尚未完成。
- “部分完成”：已有代码或页面，但还不能作为完整生产能力验收。

## 2. 当前阶段判断

项目已经从单页 HTML 原型进入“前后端核心链路可联调”的开发阶段，具备微信小程序、后端 API、数据库迁移、共享契约和基础 CI。

当前可以用于开发者工具中的内部体验，但还不能直接面向大量真实用户公开上线。下一阶段应优先补齐核心交互、真实云服务联调、自动化测试、部署监控和合规能力，不宜继续无限增加低频功能。

恢复开发时应先执行：

```powershell
git switch dev2
git pull --ff-only origin dev2
npm.cmd install
npm.cmd run check
```

启动本地联调：

```powershell
npm.cmd run dev:api
npm.cmd run dev:weapp
```

恢复后的第一批任务：

9. 完成备案、协议、隐私和用户权利链路。
10. 最后开发并开放分享广场。
11. 上线稳定后再投入制作回忆、营养分析和更复杂推荐。

## 9. 内测验收门槛

开始邀请真实家庭内测前，至少满足：

- [ ] 创建和加入厨房成功。
- [ ] 从菜谱广场收录菜谱成功。
- [ ] 两位成员先后修改同一餐不会静默覆盖。
- [ ] 菜单保存后采购清单始终正确。
- [ ] 删除菜品后独有食材正确移除，共用食材正确减量。
- [ ] 完成本餐后菜单只读，成品照仍可补充。
- [ ] 微信登录、COS 上传和采购分享在真机可用。
- [ ] 关键接口有幂等、限流和基本监控。
- [ ] 数据库存在可用备份。
- [ ] 隐私政策、反馈、数据导出和注销入口可用。
- [ ] 没有高危安全漏洞或明文密钥。

## 10. 正式上线门槛

面向大量用户公开上线前，必须进一步满足：

- [ ] 核心验收场景全部通过。
- [ ] API 成功率、延迟和核心转化可以持续观测。
- [ ] staging 验收完成。
- [ ] 生产备份、告警、费用预算和恢复演练完成。
- [ ] 微信小程序备案、域名和主体资料完成。
- [ ] 隐私政策与实际代码行为一致。
- [ ] 数据导出、注销、举报和客服链路真实可用。
- [ ] 公开内容具备自动审核和人工复核。
- [ ] 运营后台、审计、下架和封禁能力可用。
- [ ] 有明确的发布、回滚和故障联系人。
